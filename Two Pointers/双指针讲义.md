## 1. 核心思想（The big idea）

很多题目要求你考察数组中每一个**连续区间（contiguous block）**，并对每个区间算点东西——一个和、一个计数、一个最小值。最直接的做法是对每个区间都从零重新计算。如果有 `O(N)` 个区间，每个又花 `O(N)` 去求值，那就是 `O(N²)`——通常慢到拿不到满分。

关键的观察是：**相邻的两个区间几乎完全重叠**。当窗口向右滑动一步时，只有极少的部分发生变化：一个元素从左端离开，一个元素从右端进入。所以我们不重算，而是**维护一个"当前状态"，并增量式（incrementally）更新它**。

> **口诀：** 不要重算窗口，而要*修补*它——减去离开的，加上进入的。

就这一招，把每个窗口的 `O(N)` 计算变成了 `O(1)`。

---

## 2. 技巧的两种形态（Two flavours）

这个技巧有两种密切相关的模式。判断题目需要哪一种，就已经赢了一半。

**定长窗口（fixed-size window）。** 窗口宽度是一个常数（比如 `K`）。两个端点**同步**移动，每次各走一步。*Mansion* 是经典例子。

**变长窗口 / 双指针（variable-size window / two pointers）。** 两个端点**各自独立**移动。通常右端点先冲出去把窗口变"合法"，然后左端点再前进把窗口缩小。两个指针在数组上一前一后地追赶，但**谁都不会往回走**。*Wet Chairs* 是经典例子。

下面各用一道题讲清这两种形态。

## 3. 例题一：Mansion（AIO 2007）— 定长窗口

**一句话题意。** 给定一个长度为 `N` 的数组，求任意 `K` 个连续元素之和的最大值。

### 朴素做法（naive approach）

枚举每一个起点，对每个起点把 `K` 个值加起来：

```
best = 负无穷
for start = 0 to N-K:
    best = max(best, a[start .. start+K-1] 之和)
```

有 `O(N)` 个起点，每次求和花 `O(K)`，总共 `O(NK)`。当 `N`、`K` 较大时太慢。

### 滑动窗口的洞察（the insight）

看相邻的两个窗口：

```
起点为 0 的窗口:   [ a0  a1  a2 ... a(K-1) ]  aK  ...
起点为 1 的窗口:    a0  [ a1  a2 ... a(K-1)   aK ] ...
```

除了两个端点，其余全部相同。从前一个窗口到后一个窗口，我们**失去 `a0`**（旧的左端）、**得到 `aK`**（新的右端），中间的部分原封不动。于是：

```
新的和 = 旧的和 - a[离开的] + a[进入的]
```

每个窗口只需 `O(1)`。

### C++ 实现

```cpp
long long mansion(int N, int K, vector<long long>& a) {
    long long window = 0;
    for (int i = 0; i < K; i++) window += a[i];   // 先求出第一个窗口的和
    long long best = window;
    for (int i = K; i < N; i++) {
        window += a[i] - a[i - K];                // 修补，而非重算
        best = max(best, window);
    }
    return best;
}
```

### 复杂度（complexity）

建第一个窗口花一次 `O(K)`，之后每次滑动只花 `O(1)`，共 `N - K` 次。总计 `O(K + N) = O(N)`。与前缀和（prefix sum）解法复杂度相同——两者都能拿满分。用哪个看个人喜好；滑动窗口不需要额外数组。

## 4. 例题二：Wet Chairs（AIO 2015）— 变长窗口

这里就是"双指针"名副其实的地方。

**一句话题意。** 一排共有 `C` 把椅子，每把或湿或干。你要把 `N` 个朋友安排在一段**连续**的椅子上；其中最多 `K` 个人能忍受湿椅子，所以这段区间至少要有 `N` 把椅子，**并且**至少有 `N − K` 把是干的。求这段区间**最短**的长度（即最左和最右被坐的椅子之间的距离）。

### 朴素做法 — O(C²)

固定最左的椅子，然后向右走，边走边数椅子数和干椅子数，直到区间够大为止。对每一个可能的最左椅子都做一遍。

```
least_chairs_needed = C
for leftmost = 0 to C-1:
    num_chairs = 0
    num_dry = 0
    for i = leftmost to C-1:
        num_chairs += 1
        if 椅子 i 是干的:
            num_dry += 1
        if num_chairs >= N and num_dry >= N-K:
            least_chairs_needed = min(least_chairs_needed, num_chairs)
            break
```

内层循环对 `O(C)` 个最左椅子中的每一个都可能扫 `O(C)` 把椅子：`O(C²)`。这能拿部分分（子任务 1–2，约 40 分），拿不到满分 100。

### 打开 O(C) 大门的洞察：单调性（monotonicity）

这是最关键的观察。假设最左椅子是 3，能坐下所有人的最早的最右椅子是 7。现在把最左椅子前移到 4，**能坐下所有人的最早的最右椅子绝不可能小于 7**——它只能停在 7 或往更右移。

为什么？把左端从 3 移到 4，等于从区间里*拿掉*了一把椅子。拿掉一把椅子，绝不可能让一个本来就不够大的区间变得够大。所以之前成立的位置，就是现在的*下界*。右指针永远不需要往回退。

**正是这个性质保证了双指针的正确性（correctness）。** 只要你能论证"左端右移时，所需的右端也只会右移"，就能用双指针扫一遍。

### 双指针方法

维护两个指针和一个运行计数。对每一个最左椅子：

1. 若当前区间还不合法，就**把右指针往前推**（不断加入椅子）直到合法——从它*已经到达*的位置继续，而**不是**重新开始。
2. 若合法，记录区间长度。
3. **左指针前进一步**：离开的椅子退出区间，相应地把计数减掉。右指针原地不动。

因为右指针是"接着走"而不是"重置"，我们绝不会重复扫已经数过的椅子。

### C++ 实现

```cpp
// dry[i] == 1 表示椅子 i 是干的，否则为 0
int chairs(int C, int N, int K, vector<int>& dry) {
    int need_dry = N - K;          // 至少需要这么多把干椅子
    int best = C;
    int num_chairs = 0, num_dry = 0;
    int r = 0;                     // 右边界；窗口为左闭右开区间 [l, r)
    for (int l = 0; l < C; l++) {
        // 把右指针往前推，直到窗口合法（或到头为止）
        while (r < C && !(num_chairs >= N && num_dry >= need_dry)) {
            num_chairs++;
            num_dry += dry[r];
            r++;
        }
        if (num_chairs >= N && num_dry >= need_dry)
            best = min(best, num_chairs);
        // 左指针前移：椅子 l 退出窗口
        if (r > l) {               // 只有它确实在窗口内才移除
            num_chairs--;
            num_dry -= dry[l];
        } else {                   // 窗口已空；让 r 跟上 l
            r = l + 1;
        }
    }
    return best;
}
```

### 复杂度论证 — 请读两遍

乍一看这像 `O(C²)`：外层对 `l` 循环，里面还套了个 `while`。这个直觉是**错的**，而想通它为什么错，正是整个技巧的精髓。

**看指针，别看循环。** `l` 只增不减，`r` 也只增不减，二者永远不会被重置或减小。`l` 从 `0` 走到 `C`；`r` 同样从 `0` 前进到最多 `C`，而且——这是关键——它的进度在外层循环的各次迭代之间被*保留*，绝不丢弃。

所以在*整个*运行过程中，右指针总共最多走 `C` 步，左指针总共最多走 `C` 步，加起来最多 `2C` 次指针移动，每次移动是 `O(1)` 的工作。总计 `O(C)`。

这种推理叫**均摊分析（amortized analysis）**：某一次外层迭代可能干很多 `while` 循环的活，但这些活被"记账"到右指针的前进上，而右指针总共只有 `C` 个单位的进度可供支配。足够拿满分 100。

> **双指针的判定标准：** 如果你能说出"每个指针只朝一个方向移动，每个元素只进入一次、离开一次"，那么算法就是线性的——不管循环嵌套看起来多吓人。

## 5. 一个可复用的模板（A reusable template）

大多数变长窗口题都符合这个骨架：

```cpp
int l = 0;
// 初始化运行状态（和、计数、……）
for (int r = 0; r < n; r++) {
    // 把元素 r 加入状态          —— 向右扩张窗口
    while (/* 窗口"太大" / 不合法 */) {
        // 把元素 l 从状态中移除    —— 从左收缩窗口
        l++;
    }
    // 把窗口 [l, r] 当作一个候选答案来考虑
}
```

有些题反过来更清爽（外层枚举 `l`，把 `r` 往前推），就像上面 Wet Chairs 的代码。两者是同一个思想。选哪种取决于哪种能让"合法性"条件写起来最简单。

**动手写代码前先回答三个问题：**

1. **我要维护窗口的什么摘要？**（一个和、干椅子的计数、一张频次表、一个最大值……）
2. **元素进入、元素离开时，这个摘要怎么更新？** 两者都必须是 `O(1)`（或接近）。
3. **单调条件（monotonic condition）是什么**——它让指针能往前走且永不回头？找不到的话，双指针可能就不适用。

## 6. 常见坑（Common pitfalls）

**重算而不修补。** 如果你在循环里又去把整个窗口求了一遍和，那就把全部好处都丢光了。更新只能碰进入和离开的那两个元素。

**把快指针重置了。** 在 Wet Chairs 里，对每个 `l` 都重新开始 `r`，会不声不响地把你打回 `O(C²)`。右指针必须在外层各次迭代之间**保留**位置。

**边界差一（off-by-one）。** 一开始就定好窗口是闭区间 `[l, r]` 还是左闭右开 `[l, r)`，然后保持一致。左闭右开（`r` = "最后一个元素的后一位"）往往更少 `+1`/`−1` 的 bug。

**忘记移除离开的元素。** 左指针前进时，它对应的元素必须从每一个运行计数中减掉。漏一个，状态就会跑偏。

**空窗口的边界情况。** 当左指针追上右指针时，窗口为空。要保证计数不会变成负数（Wet Chairs 代码里的 `if (r > l)` 正是处理这一点）。

**没验证就假设单调性。** 双指针只有在"左端右移时所需右端也单调右移"成立时才**正确**。永远要能针对你这道具体题目说出这个论证——如果它不成立，双指针给你的是错误答案，而不只是慢。

## 8. 一页速查表（One-page reference）

|          | 定长窗口 (fixed)     | 变长窗口 / 双指针 (two pointers) |
| -------- | ---------------- | ------------------------- |
| 窗口宽度     | 常数 `K`           | 随扫描变化                     |
| 指针移动     | 两端同步移动           | 两端各自独立、且只往前               |
| 何时用      | "恰好 `K` 个的最优区间"  | "满足某条件的最短/最长区间"           |
| 进入时更新    | 加 `a[r]`         | 加 `a[r]`                  |
| 离开时更新    | 减 `a[r-K]`       | 减 `a[l]`                  |
| 为何线性     | `N` 次滑动 × `O(1)` | 每个指针总共走 ≤ `n` 步（均摊）       |
| 代表 AIO 题 | Mansion (2007)   | Wet Chairs (2015)         |

**整个技巧一句话：** 维护当前窗口的运行摘要，在两端只进不退地移动时用 `O(1)` 修补它，这一趟扫描就是线性的。
