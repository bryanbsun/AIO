# 第一题：Hiring Monks（雇用僧侣）

## 题目简述

有 N 名僧侣（每人有一个技能值）、S 个学生职位（每个有技能上限）、M 个师傅职位（每个有技能下限）。每名僧侣最多做一个职位，每个职位最多分配一名僧侣，求最多能安排多少名僧侣。

- 学生职位 j：僧侣技能 **≤ $s_j$**
- 师傅职位 k：僧侣技能 **≥ $m_k$**

---

## 第一步——理解结构

首先观察：学生职位想要**技能低**的僧侣，师傅职位想要**技能高**的僧侣。两者方向相反。所以应该先对所有数据排序（sort）。

把僧侣技能画在数轴上，学生职位"从左边伸进来"，师傅职位"从右边伸进来"。

---

## 第二步——关键观察：交换论证（Exchange Argument）

**结论：** 一定存在一个最优方案，使得所有做学生职位的僧侣的技能，都不超过所有做师傅职位的僧侣的技能。

**证明：** 假设在某个最优方案中，僧侣 A 做了学生职位，僧侣 B 做了师傅职位，但 A 的技能 > B 的技能。那么：

- B 的技能 ≤ A 的技能 ≤ 学生职位上限 → B 也能做这个学生职位。
- A 的技能 ≥ B 的技能 ≥ 师傅职位下限 → A 也能做这个师傅职位。

所以可以**把 A 和 B 对调**，安排数量不变，方案依然合法。反复对调直到所有学生职位僧侣的技能都低于所有师傅职位僧侣。

**这个结论意味着：** 在最优方案中，存在一个"分割点（split point）"k。把僧侣按技能从小到大排序后，排名前 k 的僧侣竞争学生职位，排名后 n-k 的僧侣竞争师傅职位。

```
僧侣（按技能升序排列）：[低 ... | ... 高]
                                ^ 分割点 k
左边：竞争学生职位
右边：竞争师傅职位
```

枚举每个可能的 k（从 0 到 N），取最好的结果。

---

## 第三步——分别计算两侧最优匹配

对僧侣技能升序排列，学生上限升序，师傅下限升序，定义：

- **f[k]** = 用技能最低的 k 名僧侣（x[0..k-1]），最多能填多少个学生职位
- **g[k]** = 用技能最高的 n-k 名僧侣（x[k..n-1]），最多能填多少个师傅职位

**答案 = max(f[k] + g[k])，k 从 0 到 n**

---

### 计算 f[]——正向贪心（Forward Greedy）

学生职位要求技能 ≤ 上限。对僧侣按技能升序处理，每个僧侣分配给**能容纳他的最小上限（tightest cap）**的学生职位。

**为什么"选最小上限"是最优的？** 把紧的上限留给低技能僧侣，宽松的上限留给高技能僧侣，这样不会浪费。如果把宽松上限给低技能僧侣，后来技能稍高的僧侣可能没有职位可用。

双指针（two-pointer）实现：

```
j = 0（指向已排序的学生上限数组）
for k = 1 到 n:
    跳过太小的上限：while st[j] < x[k-1] → j++
    if j < s:
        f[k] = f[k-1] + 1    （僧侣 x[k-1] 填入上限 st[j]）
        j++
    else:
        f[k] = f[k-1]         （没有合适的上限）
```

**为什么可以安全跳过那些上限？** 当 st[j] < x[k-1] 时，这个上限对当前僧侣太小，对后续技能更高的僧侣也太小——它永远不会被用到，安全丢弃。

> **DP 联系（面向有兴趣学动态规划的同学）：**
> f[k] = f[k-1] + (0 或 1)，这正是一个一维 DP（1D DP）递推式！"状态（state）"是当前考虑了多少名僧侣，"值（value）"是最大匹配数。贪心双指针只是在 O(1) 时间内告诉我们该加 0 还是加 1。

---

### 计算 g[]——反向贪心（Backward Greedy）

我们从右到左计算 g——每次把技能最低的那名僧侣加入"师傅候选池"。

对每个新加入的僧侣（从 x[n-1] 依次加到 x[0]），把他分配给**他能胜任的要求最高的师傅职位（most demanding job）**。这样可以把要求低的职位留给后续加入的技能更低的僧侣。

双指针（从右到左扫描师傅职位）：

```
j = m-1（指向最高下限的师傅职位）
for k = n-1 下降到 0:
    跳过要求太高的职位：while ms[j] > x[k] → j--
    if j >= 0:
        g[k] = g[k+1] + 1    （僧侣 x[k] 填入师傅职位 ms[j]）
        j--
    else:
        g[k] = g[k+1]         （没有合适的师傅职位）
```

**为什么"选要求最高的"是最优的？** 如果当前僧侣填了要求较低的职位，要求最高的职位可能无人能填（后续加入的僧侣技能更低）。优先填最难的职位，把简单的留给后来者，才能最大化总匹配数。

---

## 第四步——反例：朴素贪心为什么错了

很多同学会想："先用最低技能僧侣填师傅职位，再用剩下的填学生职位"。**这是错的**，下面是反例：

```
僧侣：         [5, 8, 12]
学生上限：     [9, 9]
师傅下限：     [6]
```

**朴素贪心（错误）：**
- 师傅职位（下限 6）：分配技能最低且满足条件的僧侣 → 僧侣 8。计数 = 1。
- 学生职位（上限 9）：剩余僧侣中技能最高且 ≤ 9 的 → 僧侣 5。计数 = 2。
- 学生职位（上限 9）：没有合适的僧侣。
- **输出：2（错！）**

**正确答案：3**
- 僧侣 5 → 学生职位（5 ≤ 9 ✓）
- 僧侣 8 → 学生职位（8 ≤ 9 ✓）
- 僧侣 12 → 师傅职位（12 ≥ 6 ✓）

朴素贪心"浪费"了僧侣 8：把他放到师傅职位，但其实僧侣 12 完全可以胜任，把 8 腾出来多填一个学生职位。

分割点算法会尝试 k=2（僧侣 5、8 → 学生；僧侣 12 → 师傅），得到 f[2]+g[2]=2+1=3。✓

---

## 第五步——完整追踪（样例一）

```
僧侣（升序）：  [20, 40, 100, 300, 1000]
学生上限：      [50, 110]
师傅下限：      [300, 600, 2500]
```

**f[] 计算过程：**

| k | 新加僧侣 | 操作 | f[k] |
|---|---------|------|------|
| 0 | — | — | 0 |
| 1 | 20 | st[0]=50 ≥ 20 → 匹配，j→1 | 1 |
| 2 | 40 | st[1]=110 ≥ 40 → 匹配，j→2 | 2 |
| 3 | 100 | j=2=s，无上限 | 2 |
| 4 | 300 | j=2=s，无上限 | 2 |
| 5 | 1000 | j=2=s，无上限 | 2 |

**g[] 计算过程（从右到左）：**

| k | 加入僧侣 x[k] | 操作 | g[k] |
|---|-------------|------|------|
| 5 | — | — | 0 |
| 4 | 1000 | ms[2]=2500>1000→j--；ms[1]=600≤1000→匹配，j→0 | 1 |
| 3 | 300 | ms[0]=300≤300→匹配，j→-1 | 2 |
| 2 | 100 | j=-1，无职位 | 2 |
| 1 | 40 | j=-1，无职位 | 2 |
| 0 | 20 | j=-1，无职位 | 2 |

**f[k]+g[k]：** 2, 3, **4**, 4, 3, 2

**答案 = 4** ✓（最优分割在 k=2：僧侣 20、40 → 学生；僧侣 100、300、1000 → 师傅）

---

## 时间复杂度（Time Complexity）

- 排序（sorting）：O(N log N + S log S + M log M)
- f[] 扫描：O(N + S)
- g[] 扫描：O(N + M)
- 最终枚举：O(N)
- **总计：O((N+S+M) log(N+S+M))**

N、S、M ≤ 100,000，速度完全够用。

---

## 常见错误

1. **先做师傅职位再做学生职位的朴素贪心**——顺序会影响结果，这种方法不正确（见上方反例）。

2. **忘记排序**——贪心和双指针必须在已排序的数组上进行。

3. **没想到分割点**——不用分割点的话，同时处理两类职位会复杂得多。

4. **两趟双指针共用同一个 j**——f[] 和 g[] 需要各自独立的指针。

# 第二题：Medusa's Snakes（美杜莎的蛇）

## 题目简述

蛇的 DNA 是由字母 `S, N, A, K, E` 组成的字符串。毒性等级为 x 的 DNA 是：x 个 S，接着 x 个 N，接着 x 个 A，接着 x 个 K，接着 x 个 E。可以删除任意字母，求能达到的最大毒性等级。

---

## 第一步——问题转化

删除字母等价于寻找**子序列（subsequence）**：在 DNA 中找出一个子序列，满足"S^x N^x A^x K^x E^x"的格式。答案 x 在 0 到 N/5 之间（因为 5x ≤ N）。

---

## 第二步——对答案二分（Binary Search on Answer）

**能否达到毒性等级 x？** 这是一个是/否的判断问题。关键性质：

> 如果能达到等级 x，那么一定能达到等级 x-1。

为什么？如果 DNA 里有 x 个 S，后面跟着 x 个 N……那只取前 x-1 个就能得到等级 x-1。

这种**单调性（monotonicity）**意味着：可达等级形成一段连续区间 [0, 答案]。因此可以对 x 进行**二分查找（binary search）**。

```
lo = 0，hi = N/5
while lo <= hi:
    mid = (lo + hi) / 2
    if check(mid): lo = mid + 1    ← 能达到 mid，尝试更高
    else:          hi = mid - 1    ← 不能达到 mid，尝试更低
答案 = hi
```

---

## 第三步——可行性检验（Feasibility Check）

`check(x)`：从左到右扫描字符串，**贪心地（greedily）** 先收集 x 个 S，再收集 x 个 N，依此类推。

```cpp
bool check(int x) {
    int phase = 0, count = 0;  // phase: 当前在收集哪个字母
    for (每个字符 c in DNA) {
        if (c == letters[phase]) {
            count++;
            if (count == x) {    // 当前字母收集完毕
                count = 0; phase++;
            }
        }
    }
    return phase >= 5;           // 五种字母都收集够了
}
```

**为什么贪心正确？** 收集 S 时，尽量早取。推迟取某个 S 只会让后面能用的字符更少，不可能更好。同样的论证适用于 N、A、K、E 的每一阶段。"尽早取"的贪心策略永远不比"等待"差。

---

## 第四步——逐步追踪（样例一）

字符串：`KSEESNANNAAKNKESE`，`check(2)`：

| 位置 | 字符 | 阶段（Phase） | 计数（Count） | 操作 |
|------|------|--------------|--------------|------|
| 0 | K | S(0) | 0 | 跳过 |
| 1 | S | S(0) | 1 | 收集 |
| 2 | E | S(0) | 1 | 跳过 |
| 3 | E | S(0) | 1 | 跳过 |
| 4 | S | S(0) | 2 | 收集 → 进入 N 阶段 |
| 5 | N | N(1) | 1 | 收集 |
| 6 | A | N(1) | 1 | 跳过 |
| 7 | N | N(1) | 2 | 收集 → 进入 A 阶段 |
| 8 | N | A(2) | 0 | 跳过 |
| 9 | A | A(2) | 1 | 收集 |
| 10 | A | A(2) | 2 | 收集 → 进入 K 阶段 |
| 11 | K | K(3) | 1 | 收集 |
| 12 | N | K(3) | 1 | 跳过 |
| 13 | K | K(3) | 2 | 收集 → 进入 E 阶段 |
| 14 | E | E(4) | 1 | 收集 |
| 15 | S | E(4) | 1 | 跳过 |
| 16 | E | E(4) | 2 | 收集 → 完成！ |

phase = 5 ≥ 5 → 返回 `true`。等级 2 可达 ✓

`check(3)` 需要 3 个 S。位置 15 才能收集到第 3 个 S，但之后没有字符能再收集 3 个 N。返回 `false`。故答案 = 2 ✓

---

## 第五步——二分过程追踪（样例二）

字符串：`SSSSNNNAAAAKKKKEEEEEEE`，N=22，hi=4。

| lo | hi | mid | check(mid) | 结果 |
|----|----|----|-----------|------|
| 0 | 4 | 2 | 4个S取2、4个N取2…轻松 → true | lo→3 |
| 3 | 4 | 3 | 4个S取3、4个N取3…勉强够 → true | lo→4 |
| 4 | 4 | 4 | 4个S取4、3个N不够 → false | hi→3 |
| 4 > 3 | 退出 | | | **答案 = hi = 3** ✓ |

---

## 时间复杂度（Time Complexity）

- 二分：O(log(N/5)) = O(log N) 轮
- 每次 `check`：O(N)
- **总计：O(N log N)**

N ≤ 100,000，非常快。

---

## 常见错误

1. **没想到二分**——可能会从 x=0 逐一往上试，总复杂度 O(N²)；或者只看每个字母的数量、忽略顺序。

2. **二分上界设错**——用 `hi = N` 而非 `N/5`，逻辑不影响正确性（二分仍然有效），但浪费了几轮迭代。

3. **check 函数写错**——常见错误：切换 phase 时忘记重置 count，或者比较了错误的字母。

4. **没处理 x=0 的情况**——空子序列（empty subsequence）永远合法，x=0 必须返回 true。当 DNA 中完全没有合法子序列时，答案为 0。

---

## DP 联系（面向有兴趣学动态规划的同学）

**Medusa's Snakes** 的贪心检验本质上是一个压缩到 O(1) 空间的 DP：

定义 `dp[phase]` = 当前阶段已收集了多少字母。我们扫描字符串时不断更新它。由于每个阶段只有在上一阶段完成后才开始，整个"DP 表"退化为两个变量（`phase` 和 `count`）。这就是一维 DP 在空间上的极致优化。

更通用的 DP 思路（不用二分）：设 `dp[i]` = 只看前 i 个字符，最大可达毒性等级是多少。这可以用 O(N²) 时间解决。二分 + 贪心把它优化到 O(N log N)，利用的正是**单调性（monotonicity）**。

这是竞赛中非常经典的模式：**对答案二分（binary search on answer）+ 贪心/DP 可行性检验（feasibility check）**。当你看到"求满足某条件的最大 x"时，立即问自己：这个条件关于 x 是单调的吗？可行性能快速判断吗？

---

**Hiring Monks** 的 f[] 和 g[] 同样有 DP 的味道：

```
f[k] = f[k-1] + (0 或 1)
g[k] = g[k+1] + (0 或 1)
```

每个状态只依赖上一个状态，这就是 DP 的**最优子结构（optimal substructure）**原则：不需要记住完整的分配方案，只需要记住已匹配的数量。这正是 DP 的核心力量。

---

## 总结

| 题目 | 核心技巧 | 关键洞察 |
|------|---------|---------|
| Hiring Monks（雇用僧侣） | 贪心（Greedy）+ 双指针（Two Pointers） | 交换论证（Exchange Argument）→ 分割点（Split Point）→ 独立计算 f[] 和 g[] |
| Medusa's Snakes（美杜莎的蛇） | 对答案二分（Binary Search on Answer）+ 贪心检验（Greedy Check） | 可达性单调（Monotonicity）→ 二分；从左到右贪心扫描（greedy left-to-right scan）→ O(N) 检验 |

两道题都需要问自己：**"能排序后顺序处理吗？"**和**"最优方案是否隐藏着更简单的结构？"**
