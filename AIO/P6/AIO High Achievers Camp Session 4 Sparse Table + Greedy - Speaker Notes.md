**第 4 页 · When do we need it?**

先讲清楚 Sparse Table 解决什么问题、为什么用它，再讲它怎么做。今天三道题都要用到它（或它的思想），所以开场先把应用场景讲透。  
场景：一个固定的数组，N 个数，然后有 Q 个询问"a[l..r] 的最大值是多少"。以 N = Q = 10^5 为例比较四种做法：  
1. 每次直接扫：不用预处理，但每次 O(N)，一共 N · Q = 10^10，太慢。  
2. 把所有区间的答案都存下来：区间有约 N²/2 = 5 × 10^9 个，光是填表就要这么多时间，内存也放不下。时间和空间同时超。  
3. Sparse Table：只存长度是 2 的幂的区间，约 N log N ≈ 1.7 × 10^6 个，查询仍然 O(1)。它正好落在"全存"和"不存"之间，是一个折中，而且是很好的折中。  
4. 线段树：O(N) 空间、每次 O(log N)，还支持修改。这几题用线段树也能过；选 Sparse Table 是因为数组不修改、代码最短、查询最快。  
所以，"一定要常数时间"并不是必须的，Sparse Table 是"刚好够用、最省事"的选择。  
什么时候想到 Sparse Table：三个条件同时满足。① 数组是静态的（读入后不改）；② 询问很多，值得先花 O(N log N) 预处理；③ 运算允许重叠：max、min、gcd 把同一个数算两次不影响结果。求和不行（重叠部分会被算两次），区间和用 prefix sum。  
名字的由来：如果把所有区间的答案都存下来，是一张 N × N 的"稠密"（dense）表；Sparse Table 只存其中长度为 2 的幂的那一小部分（约 N log N 个），所以叫"稀疏表"。这个名字一般认为出自 Bender 和 Farach-Colton 2000 年的论文 The LCA Problem Revisited。  
提问：如果题目中途会修改数组，还能用 Sparse Table 吗？答案：不能，改一个数要更新 log N 层里很多格子；这时用线段树。

**第 5 页 · Max of any range in O(1)**

放映时按键（或点击）逐步显示红色答案：①sp[1] 行 ②sp[2] 行 ③k ④两个起点 ⑤答案。先让学生在纸上填，再一下一下揭晓。  
答案：sp[1] = 3 4 4 5 9 9 6。sp[2] = 4 5 9 9 9。  
查询 [2, 7]：长度 6，k = 2（≤ 6 的最大 2 的幂是 4）。max(sp[2][2], sp[2][4]) = max(5, 9) = 9。  
要点：两个长度为 4 的块有重叠（位置 4、5 被算了两次）。对 max 和 min 没关系，但对求和不行：所以求和要用 prefix sum。  
预处理 O(N log N)，查询 O(1)。数组不能被修改。

**第 6 页 · Why powers of 2?**

为什么块长取 2 的幂，而不是别的？  
先看查询需要什么：查一个长度为 L 的区间，希望只用两块就盖住它：一块从左端开始，一块在右端结束，两块一样长。要盖满，块长至少要有 L/2。所以条件是：对每一个长度 L，表里都要有一种块长落在 [L/2, L] 之间。  
2 的幂刚好满足：取 k = ⌊log₂ L⌋，就有 2^k ≤ L < 2^(k+1)，也就是 L/2 < 2^k ≤ L。  
图中例子：查 [2, 14]，L = 13，k = 3，块长 8。两块是 a[2..9] 和 a[7..14]，中间 7..9 重叠，对 max 没关系。  
右边的表：存哪些块长？  
- 所有长度都存：一块就够，但要 N 层，也就是 O(N²) 个答案，回到"全存"。  
- 2 的幂：log₂ N ≈ 17 层，每次查询 2 块。  
- 3 的幂：层数少一些（log₃ N ≈ 11），但块长只保证 ≥ L/3，每次查询最多要 3 块。  
这本身又是一个折中：底数越大，层数越少，但每次查询要拼的块越多。2 的幂是最自然的选择：相邻两层块长正好翻倍，是"保证每个 L 都有 [L/2, L] 里的块"所需的最少层数。  
另一个好处是建表简单：长 2^k 的块正好由两个长 2^(k−1) 的块拼成，sp[k][i] = max(sp[k−1][i], sp[k−1][i + 2^(k−1)])，一次 max 就算完。查询时的 k 用预处理的 lg[] 数组直接取。  
提问：查 [5, 5]（L = 1）时 k 是多少？两块是什么？答案：k = 0，两块都是 a[5] 自己。

**第 7 页 · Build once, ask many times**

2^17 = 131072 > 10^5，17 层就够了，开 20 层更保险。lg[1] = 0，因为全局数组初始为 0。求区间最小值时把 max 改成 min。和 prefix sum 对比：两者都是"先预处理，再快速回答每个区间问题"。

**第 8 页 · Three problems, one idea**

今天三道题都用到 Sparse Table 或它的思想，先给学生一张"地图"，讲每道题时再回到这里。  
1. Ladybugs II：最标准的用法。把起点 D 从式子里分离出来以后，f1(l) = P[r] − 2P[l] 和 f2(l) = 2P[r] − P[l] 只和窗口有关，是静态数组。每个询问先二分定位 D，再在一段 l 上求 f1、f2 的最小值。每次扫一遍是 O(N)，乘上 Q 个询问就超时；用 Sparse Table 每个询问 O(log N)（二分）+ O(1)（查最值）。瓶颈是"询问太多"。  
2. Robot Writing：二分里套区间最大值。要找"从 p 往左最远到哪，使 T[l..p] 都 ≤ v"，这个条件关于 l 单调，所以二分；二分每一步都要问一次区间最大值。整个算法要做很多次扩展，每次 O(log N)，总计 O((N + M) log N)。这里 Sparse Table 不是唯一选择，单调栈也可以（讲义里的思考题），但 Sparse Table + 二分最直接。  
3. Beach Umbrellas：用的是同一个倍增思想，但存的不是区间最大值，而是"从结点 i 跳 2^p 次到哪里、花几把伞"（binary lifting，倍增跳表）。原因是 K 可达 10^9，一步一步模拟"用 j 把伞走到哪"不可能；把 j 写成二进制，最多跳 log 次。瓶颈是"步数太多"。  
共同点：只存 2 的幂长度（或 2 的幂步数）的信息，查询时用二进制拆开再拼回去。  
提问：Ladybugs 和 Robot Writing 的瓶颈分别是什么？答案：Ladybugs 是询问太多（每个询问都要一个区间最值）；Robot Writing 是扩展次数多，而且每次扩展里的二分要反复问区间最大值。

**第 9 页 · Ladybugs II**

约 25 分钟。第一次用 Sparse Table。这里的 Two Pointers 指的是"K 个连续元素组成的滑动窗口"这个想法。

**第 10 页 · The problem**

在右侧画数轴，标出 P = 1、4、6（样例 1），K = 2。再标出三个询问 D = 0、5、2。

**第 11 页 · The K ladybugs are always consecutive**

先问：为什么一定是连续的？让学生在数轴上论证。
答案：在一条线上从最左走到最右，中间的瓢虫都会被经过，签名白拿；所以只要有更远的瓢虫被选上，中间的就可以换进来而不增加时间。
和今天后面的 Beach Umbrellas 呼应：那里的答案也是一整段连续区间。

**第 12 页 · Three kinds of window**

前两种情况各 O(1)。第三种是难点：每个询问最多 K − 1 个窗口，Q 个询问，K 和 Q 都大时太慢。
提问：有多慢？答案：Q × K，例如 10^10。

**第 13 页 · Pull D out of the formula**

这是本题最重要的想法：只和窗口有关的量都可以预处理。和 prefix sum 是同一种思路：把不依赖询问的部分先算好。

**第 14 页 · Sample 1**

放映时按键（或点击）逐步显示红色答案：①–③ D = 0、5、2 各一行。先让学生在纸上填，再一下一下揭晓。  
答案：  
D = 0：s = 1。全在右边：l = 1，4 − 0 = 4。没有全在左边的，也没有跨过 D 的。答案 4。  
D = 5：s = 3。全在右边：无。全在左边：以第 2 只结尾的窗口 [1, 4]，5 − 1 = 4。跨过 D：l = 2（[4, 6]）：2 + min(1, 1) = 3。答案 3。  
D = 2：s = 2。全在右边：l = 2，6 − 2 = 4。全在左边：无。跨过 D：l = 1（[1, 4]）：3 + min(1, 2) = 4。答案 4。  
期望输出：4 3 4。

**第 15 页 · Precompute, then answer**

用 long long。每个询问：一次 Binary Search O(log N)，加上三种情况各 O(1)。Subtask 台阶：Q = 1 → 枚举所有窗口；K = N → 只有一个窗口；完整 → Binary Search + Sparse Table。

**第 16 页 · From O(Q · K) to O((N + Q) log N)**

复杂度回顾（N, Q ≤ 100 000）：  
先要观察到：K 只瓢虫一定是连续的一段，所以只有 N − K + 1 个窗口；每个询问都试一遍是 O(Q·N) ≈ 10¹⁰。  
Binary Search 找到 D 在哪里后，全在左边、全在右边的情况各 O(1)，但跨过 D 的窗口最多 K − 1 个，O(Q·K) 仍可能到 10¹⁰。  
关键：把 D 从公式里拿出来，剩下的只和窗口有关，预处理两个 Sparse Table，区间最小值 O(1)：总共 O(N log N + Q log N) ≈ 3.4×10⁶。

**第 17 页 · Robot Writing**

约 30 分钟。这里的 "Greedy" 指的是一个 Greedy 风格的 key observation（机器人最后总是拿着较大的值），而不是我们做的某个贪心选择。

**第 18 页 · The problem**

Brute force：枚举起点和每一步的方向，2^M 种，只能过极小的 subtask。我们需要弄清楚交换到底做了什么。

**第 19 页 · Simulate sample 1**

放映时按键（或点击）逐步显示红色答案：①–④ 第 1 到 4 步各一行。先让学生在纸上填，再一下一下揭晓。  
答案：  
第 1 步：在格子 3，记录 1，移到 4（值 2），2 > 1 不交换，T = 2 3 1 2 3。  
第 2 步：在格子 4，记录 2，移到 3（值 1），1 < 2 交换，T = 2 3 2 1 3。  
第 3 步：在格子 3，记录 2，移到 2（值 3），不交换，T = 2 3 2 1 3。  
第 4 步：在格子 2，记录 3。  
记录下来的是 1 2 2 3 = S，所以 YES。  
要注意到的规律：机器人脚下的值从来不会变小。

**第 20 页 · The robot carries the maximum**

这一行就把题目里所有的交换都消掉了。较小的值被推到机器人身后，之后再也不重要。Greedy 的味道：机器人总是留下较大的那个数。

**第 21 页 · Trapped in a region**

在右侧把 T 画成柱子，在 v 处画一条水平线：区域就是线下方的那段谷。和第 3 次课的水位线图对比。找左端点：最小的 l 使 max(T[l..p]) ≤ v，这关于 l 单调，所以用 Binary Search + Sparse Table。

**第 22 页 · Arrive exactly on time**

这个奇偶性论证在很多网格题里都出现过（2019 P5 Evading Capture 也用到奇偶距离）。
提问：为什么第一次升级之后，区域总是至少有 2 格？
答案：新区域包含原来的区域加上新踩上的那一格。

**第 23 页 · Layer by layer**

放映时按键（或点击）逐步显示红色答案：①–③ 值 2、3、4 各一行 ④样例 3。先让学生在纸上填，再一下一下揭晓。  
答案（样例 2）：  
值 2，第 1 步首次出现：格子 2，区域 [1, 2]（2 格，OK）。  
值 3，第 4 步首次出现：目标格子 3（区域右侧，值 3 ✓），d = 1，dt = 3，3 − 1 = 2 是偶数 ✓。区域变成 [1, 3]。  
值 4，第 5 步首次出现：目标格子 4（值 4 ✓），d = 1，dt = 1 ✓。  
最后一层之后在区域内来回走即可。YES。  
样例 3：起点格子 1，区域 [1, 1] 只有 1 格，第 2 步必须离开，记录到 2。NO。

**第 24 页 · Two small helpers**

主循环：把 S 分成若干层（值 lv[k]，首次出现的步数 ti[k]；不要叫 tm，会和系统里的名字冲突）。维护当前层所有可能的位置；对每个位置用 extendLeft/extendRight 求出 [l, r]，检查 l − 1 和 r + 1 两个格子，合格的加入下一层（用 mark[] 去重）。每个格子最多出现在一层里，所以总复杂度 O((N + M) log N)。
常见错误：只要目标格子比 v 大就接受；必须恰好等于新的值。

**第 25 页 · From 2^M to O((N + M) log N)**

复杂度回顾（N, M ≤ 200 000）：  
暴力：枚举起点和每一步的方向，2^M。  
关键观察（Greedy 风格）：机器人脚下永远是走过的最大值，交换可以忽略；只要知道每一层能在哪个区域里走动。逐格扫描找区域是 O(N·M) ≈ 4×10¹⁰。  
用 Sparse Table 求区间最大值 + Binary Search 找区域的左右端点（extendLeft / extendRight），每个格子最多出现在一层里：总共 O((N + M) log N) ≈ 7×10⁶。

**第 26 页 · Beach Umbrellas**

约 25 分钟。整个课程最难的题。今天的目标：Greedy 的想法、反例，以及一条清楚的通往 subtask 4 的路线。完整解法作为课后阅读。

**第 27 页 · The problem**

相邻也要合并：[2, 4] 和 [5, 6] 合并成 [2, 6]。K × X 可达 10^18，要用 long long。Subtask 1（K = 0）就是合并区间后找最长的 block。

**第 28 页 · Fill each gap separately?**

放映时按键（或点击）逐步显示红色答案：①第一把伞放 3–5（跨过 block [4]）②第二把伞放 8–10：覆盖 3..10，长度 8。先让学生在纸上填，再一下一下揭晓。  
已覆盖的 block 是 [4]、[6, 7]、[9, 10]。让全班在空白行里放 2 把伞。  
错误想法：gap {3}、{5}、{8} 各需要 1 把伞；2 把伞最多连起两个 gap，例如 3..7 或 4..10，长度 7。  
正确做法：一把伞放 3–5（跨过格子 4，同时盖住 gap 3 和 gap 5），另一把放 8–10。覆盖 3..10，长度 8。  
当 X = 1 时（subtask 2），按 gap 分开算是对的：伞不可能跨过任何东西。这就是用 Two Pointers 的 subtask。

**第 29 页 · Fix the left end l**

这是经典的区间覆盖（interval covering）Greedy。一句话的 exchange argument：把任何一把伞移到左端贴住第一个未覆盖的格子，覆盖段只会变长。这个 brute force 留着做对拍。

**第 30 页 · Where should l be?**

放映时按键（或点击）逐步显示红色答案：①l = 4 ②l = 1 ③最优 ④在上面的格子里画出最优放法。先让学生在纸上填，再一下一下揭晓。  
答案：  
l = 4：伞放 6–7、8–9、10（第三把被海滩尽头截断，只盖 1 格）。4..10，长度 7。  
l = 1：伞放 1–2、3，接上 block，再放 6–7。1..7，长度 7。  
最优：伞放 2–3、6–7、8–9 → 2..9，长度 8。最优的左端 2 在 gap 的中间！  
结论："从 1 或从某个 block 开始"听起来对，其实是错的。右边被海滩尽头浪费了半把伞，不如把它放到左边。

**第 31 页 · Slide left until you touch a block**

用反例验证：B = [4, 5]，st_B = 4，X = 2，i = 1 得到 l = 2，正是我们找到的最优答案。和第 3 次课一样的 Greedy 三步法：猜规则，取一个违反规则的最优解，平移 / 交换说明它不会更差。

**第 32 页 · Right side first, unless the beach ends**

如果 K 把伞从 B 出发都到不了 N，就全部放右边。第二种方案避免浪费最后那把会在 N 处被截断的伞（正是反例里发生的情况）。这样候选从 O(U · K) 减少到 O(U)。

**第 33 页 · How far do j umbrellas go?**

只给强的学生。第 2 步的做法：从右往左扫描所有 block，用一棵按"模 X 的余数"建的线段树（segment tree），每个 block 覆盖一段余数。Binary lifting 和 Sparse Table 是同一种倍增思想：sp[k] 覆盖 2^k 个格子，up[p] 覆盖 2^p 次跳转。完整代码：P6 文件夹里的 2020_P6_Beach_Umbrellas.cpp。

**第 34 页 · The subtask ladder**

比赛建议：subtask 1–4 只用到今天讲的想法，而且分值占很大比重。先拿稳它们，再去追完整解法。
常见错误：按 gap 分开算 ceil(g / X)；只尝试 block 的起点；伞超出 N；忘了合并相邻的区间；int 溢出。

**第 35 页 · From O(N · K) to O(U log U)**

复杂度回顾（N, K ≤ 10⁹，U ≤ 100 000）：  
暴力：每个左端 l 都用 Greedy 一把一把放伞，O(N·K)，N、K 都可达 10⁹。  
subtask 4（K ≤ 5）：exchange argument 说明最优左端只有 O(U·K) 个候选，从每个候选跑一次 Greedy。  
完整解法：从一个 gap 的起点开始，一把一把放伞会"跳"到下一个 gap 的起点，形成跳转图；用 binary lifting（和 Sparse Table 同样的倍增思想）存 2^p 次跳转，"j 把伞能走多远"只要 O(log U)：总共 O(U log U)，和 N、K 的大小无关。

**第 36 页 · Write Ladybugs II**

常见 bug：跨过 D 的区间 lo/hi 差一（lo = max(1, s − K + 1)，hi = min(s − 1, w)）；忘了 s = N + 1 的情况（D 在所有瓢虫右边）；2 * p 用 int 溢出；sp 数组开小了。
样例答案：4 3 4。

**第 39 页 · Why build lg[] yourself?**

课外读物：为什么 Sparse Table 的代码要自己预处理 lg[]，而不是调用标准库的 log 或 log2？  
1. 精度：我们要的是 ⌊log₂ L⌋ 这个整数。log/log2 的结果是浮点数，只要算出 2.9999999… 而不是 3，取整就差 1。实测（GCC，x86）：double 版的 (int)log2(i) 和 (int)(log(i)/log(2)) 在 1 到 2^30 都对，但这是数学库实现得好，C++ 标准并不保证；float 版的 logf 在 31 个 2 的幂里错了 4 个。差 1 的后果：k 小了，两块盖不满区间，答案偶尔错；k 大了，块比区间长，数组越界。而且只在个别长度上出错，样例很难测出来。  
2. lg[] 只用整数运算，永远精确：lg[1] = 0，lg[i] = lg[i/2] + 1。道理是 i 和 ⌊i/2⌋ 的二进制只差最后一位，最高位的 1 正好低一位，所以 ⌊log₂ i⌋ = ⌊log₂ ⌊i/2⌋⌋ + 1。建表 O(N)。  
3. 附带好处：查表是一次数组访问，比调用 log 快（这几题差别只有几毫秒，不是关键）；而且 log2 是 C++11 才正式进入  的，C++98 只能写 log(x)/log(2)，恰好是最容易出精度问题的写法。  
其他精确写法（学生可能在别人代码里见到）：31 − __builtin_clz(L) 和 __lg(L) 是 GCC 内置的，std::bit_width(L) − 1 是 C++20 标准写法。课上统一用 lg[] 最稳妥。
