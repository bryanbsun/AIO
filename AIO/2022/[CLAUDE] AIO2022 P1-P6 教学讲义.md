## Problem 1：Election II（选举 II）

### 题意速览
给定 `N` 张选票，每张投给 A / B / C 三位候选人之一。统计得票最多的人；若最高票数被两人及以上并列，输出 `T`。

### 算法思路
最基础的**计数 / 枚举（Counting / Enumeration）**：遍历字符串统计三个候选人的票数，找出最大值，再看有多少人达到这个最大值。

- 子任务 1（N=2）、子任务 2（只有 A/B）都只是子任务 3（一般情况）的特例，写一个通用算法即可满分，**不需要针对子任务单独处理**——这是本题最大的教学点：**先看能不能一次性拿满分，而不是急着写多份代码**。

### 复杂度
时间 O(N)，空间 O(1)（只需要三个计数器）。

### C++ 代码
```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    string s;
    cin >> n >> s;

    int cnt[3] = {0, 0, 0}; // cnt[0]=A, cnt[1]=B, cnt[2]=C
    for (char c : s) {
        if (c == 'A') cnt[0]++;
        else if (c == 'B') cnt[1]++;
        else cnt[2]++;
    }

    int mx = max({cnt[0], cnt[1], cnt[2]});
    int ties = 0, winner = -1;
    for (int i = 0; i < 3; i++) {
        if (cnt[i] == mx) { ties++; winner = i; }
    }

    if (ties > 1) cout << "T" << endl;
    else cout << (char)('A' + winner) << endl;

    return 0;
}
```

### 本题要点
- **枚举 / 计数（Enumeration / Counting）**：把"找最多"问题转化为"先数出所有可能，再取最大值"。
- **不要被子任务吓到**：子任务往往只是提示你"先想简单情形"，但通用算法常常能同时通过所有子任务。

## Problem 2：Level Ground（平坦地面）

### 题意速览
`N` 段山脉，第 `i` 段海拔 $A_i$。选出一段**连续（Contiguous）**且**海拔全部相同**的区间，最大化"长度 × 海拔"。

### 算法思路
因为区间内所有海拔必须相同，本质上就是把序列按**连续相同元素分组（Run-Length Grouping）**，用**双指针（Two Pointers）**扫一遍：每遇到一段值相同的连续区间，就计算 `长度 × 值`，更新答案。

- 子任务 1（N ≤ 1000）：即使写 O(N²)（枚举区间起点终点）暴力也能过，适合作为第一步验证思路。
- 子任务 2（无特殊限制）：需要 O(N) 做法，也就是双指针分组法。

### 复杂度
时间 O(N)，空间 O(1)（除输入数组外）。

### C++ 代码
```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    cin >> n;
    vector<long long> a(n);
    for (auto &x : a) cin >> x;

    long long ans = 0;
    int i = 0;
    while (i < n) {
        int j = i;
        while (j < n && a[j] == a[i]) j++; // 找到这一段相同海拔的右边界
        long long len = j - i;
        ans = max(ans, len * a[i]);
        i = j; // 跳到下一段
    }

    cout << ans << endl;
    return 0;
}
```

### 本题要点
- **双指针（Two Pointers）**：当"区间必须满足某种连续性质"时，用双指针一次扫描代替嵌套循环，是把 O(N²) 降到 O(N) 最常见的手段之一。
- **先暴力再优化**：暴力枚举所有区间（O(N²)）能帮你验证思路是否正确，再去想如何用双指针加速。

## Problem 3：TSP（番茄销售员）

### 题意速览
连续 `N` 天卖番茄，第 `i` 天卖出数量必须落在 $[L_i, R_i]$ 之间，且**每天卖出的数量不能少于前一天**（非递减）。问是否存在可行方案。

### 算法思路
这是一道经典的**贪心（Greedy）**题。核心想法：

> 如果今天能卖的数量有多个选择，**卖最少的那个总是不会更差**——因为"今天卖得少"只会让明天的下限要求更宽松，不会让明天更难满足。这种"选择局部最优不会让整体变差"的证明方法叫**交换论证（Exchange Argument）**，是证明贪心算法正确性最常用的手段。

所以维护一个变量 `prev`（前一天卖出的数量），对每一天：
1. 今天的下限是 $\max(L_i, \mathrm{prev})$（既要满足今天的最低要求，也不能比昨天少）。
2. 如果这个下限超过了 $R_i$，说明无解，直接输出 `NO`。
3. 否则取这个下限作为今天卖出的数量（贪心地取尽量小的值），更新 `prev`。

- 子任务 1（$L_i = R_i$）：每天数量固定，本质是检查 `L` 数组是否非递减。
- 子任务 2（N=2，数值很小）：可以用二重循环暴力枚举两天的具体数量验证是否存在合法组合。
- 子任务 3（一般情况）：上面的贪心 O(N) 做法即可满分。

### 复杂度
时间 O(N)，空间 O(1)（不需要存下整个数组，边读边判断也可以）。

### C++ 代码
```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    cin >> n;
    vector<long long> L(n), R(n);
    for (auto &x : L) cin >> x;
    for (auto &x : R) cin >> x;

    long long prev = 0; // 第 0 天不存在，下限视为 0
    bool ok = true;
    for (int i = 0; i < n; i++) {
        long long today = max(L[i], prev); // 贪心：取今天能达到的最小值
        if (today > R[i]) { ok = false; break; }
        prev = today;
    }

    cout << (ok ? "YES" : "NO") << endl;
    return 0;
}
```

### 另一种视角：前缀最大值 / 后缀最小值
还可以换一个角度理解本题（这个技巧在 Problem 4、Problem 6 里也会用到）：

- 因为数列非递减，第 `i` 天卖出的数量**至少**是 $l[i] = \max(L_1, L_2, \ldots, L_i)$（**前缀最大值，Prefix Maximum**）。
- 同理，第 `i` 天卖出的数量**至多**是 $r[i] = \min(R_i, R_{i+1}, \ldots, R_N)$（**后缀最小值，Suffix Minimum**）。
- 只要对每个 `i` 检查 `l[i] <= r[i]`（等价地，检查相邻的 `l[i] <= r[i+1]`），就能判断可行性。

两种写法本质等价，但"一次遍历的贪心模拟"更直观，推荐作为主要思路来讲解；前缀/后缀数组的写法则是训练"前缀和类"思维的好机会。

### 本题要点
- **贪心 + 交换论证（Greedy + Exchange Argument）**：证明"每步取最小可行值最优"。
- **前缀最大值 / 后缀最小值（Prefix Max / Suffix Min）**：处理"必须满足所有前面（或后面）约束"类问题的通用工具。

## Problem 4：Beautiful Buildings（美丽建筑）

### 题意速览
`N` 栋楼排成一排，**丑陋度（Ugliness）** 定义为相邻楼高度差绝对值之和。最多可以修改**一栋**楼的高度（改成任意整数），求修改后能达到的最小丑陋度。

### 算法思路
关键观察：改变第 `i` 栋楼的高度，**只会影响它和左右邻居之间的两条边**（`|H[i-1]-H[i]|` 和 `|H[i]-H[i+1]|`），其余的边完全不受影响。

那么，把第 `i` 栋楼的高度改成 `H[i-1]`（或 `H[i+1]`）之后，这两条边之和变成了 `|H[i-1] - H[i+1]|`。根据**绝对值三角不等式（Triangle Inequality）**：

```
|H[i-1] - x| + |x - H[i+1]| >= |H[i-1] - H[i+1]|   对任意 x 成立
```

取 `x = H[i-1]`（或 `H[i+1]`）时等号成立，所以 `|H[i-1] - H[i+1]|` 就是修改第 `i` 栋楼之后，这两条边之和能达到的**理论最小值**，无法更优。

于是，修改第 `i` 栋楼能带来的丑陋度减少量是：

```
delta[i] = (|H[i-1]-H[i]| + |H[i]-H[i+1]|) - |H[i-1]-H[i+1]|
```

（`delta[i]` 恒 ≥ 0，由三角不等式保证。）对于两端的楼（`i=1` 或 `i=N`），修改它可以直接把与唯一邻居的那条边清零，即 `delta = |H[i] - 邻居|`。

最终答案 = 原始丑陋度 − 所有 `delta[i]` 中的最大值（也可以选择不修改任何楼，对应 `delta=0`，代码中把 `best` 初始化为 0 就自然包含了这种情况）。

- 子任务 1（高度非递减）：此时序列本身单调，任何 `delta[i]`（内部楼）恒为 0，答案就是原始丑陋度，帮助理解"单调时改中间的楼没有用"。
- 子任务 2/3（N、H 值都很小）：可以用 O(N²) 暴力——枚举修改哪栋楼、改成哪个高度（高度范围只需枚举到左右邻居之一，因为最优修改值必是某个邻居的高度）。
- 子任务 4（一般情况）：上面的 O(N) 公式法即可满分。

### 复杂度
时间 O(N)，空间 O(1)。

### C++ 代码
```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    cin >> n;
    vector<long long> h(n);
    for (auto &x : h) cin >> x;

    long long ugliness = 0;
    for (int i = 0; i + 1 < n; i++)
        ugliness += abs(h[i] - h[i + 1]);

    long long best = 0; // 最大可减少量（不修改任何楼时为 0）
    for (int i = 0; i < n; i++) {
        long long delta;
        if (i == 0)
            delta = abs(h[0] - h[1]);
        else if (i == n - 1)
            delta = abs(h[n - 2] - h[n - 1]);
        else
            delta = abs(h[i-1] - h[i]) + abs(h[i] - h[i+1]) - abs(h[i-1] - h[i+1]);
        best = max(best, delta);
    }

    cout << (ugliness - best) << endl;
    return 0;
}
```

> **小提醒**：也可以用一个等价、更"技巧化"的公式：当 `(H[i-1]-H[i])*(H[i]-H[i+1]) >= 0`（即楼高在此处单调，非峰非谷）时 `delta=0`；否则 `delta = 2*min(|H[i]-H[i-1]|, |H[i+1]-H[i]|)`。两个公式数学上等价，第一种（本讲义采用的）更直观，推荐教学时优先讲这一种。

### 本题要点
- **绝对值三角不等式（Triangle Inequality）**：`|a-x|+|x-b| >= |a-b|`，等号在 `x` 取 `a` 或 `b`（或介于两者之间）时成立。这是处理"只能修改一个点"类贪心问题时非常常见的工具。
- **局部影响分析**：先想清楚"改一个位置到底会影响哪些项"，往往能把一个看似全局的问题化简成对每个位置独立计算的公式。

## Problem 5：Composing Pyramids（谱写金字塔）

### 题意速览
给定长度为 `N` 的序列 `P`。**音乐金字塔（Musical Pyramid）** 是形如 `v, v+1, ..., m, m-1, ..., v+1, v` 的序列（先严格 +1 上升到顶点 `m`，再严格 -1 下降回到 `v`；长度恒为奇数；单个数字也算金字塔）。

求最少删除多少个数，能让剩下的**子序列（Subsequence，顺序不变，可以不连续）**变成一个音乐金字塔。

**这是六题中最难的一题**，答案 = `N - 最长金字塔子序列的长度`。

### 算法思路一（O(N²)，不需要 DP，适合拿子任务 1、2 的分）

任何金字塔都有唯一一个"顶点"位置。**固定顶点位置 `i`**，问题拆成两个互不干扰的子问题：

- `up[i]`：以 `P[i]` 结尾、"连续 +1 上升"的最长子序列长度（只看 `P[1..i]`）。
- `down[i]`：以 `P[i]` 开头、"连续 -1 下降"的最长子序列长度（只看 `P[i..N]`）。

有了 `up[i]` 和 `down[i]`，两侧能同时达到的最大半径是 `radius = min(up[i]-1, down[i]-1)`（`-1` 是因为 `up[i]`/`down[i]` 数的是"点数"而不是"下降/上升的步数"，这是最容易出 bug 的地方，一定要小心 **off-by-one**）。以 `i` 为顶点的最长金字塔长度就是 `2*radius + 1`。对所有 `i`取最大值，就是全局最长金字塔子序列长度。

**如何不用 DP 求出 `up[i]`（贪心匹配引理，Greedy Matching Lemma）**：

要计算 `up[i]`，就是要在 `P[1..i-1]` 中，按从右往左的顺序，依次找到值为 `P[i]-1, P[i]-2, P[i]-3, ...` 的位置。

> **引理**：从右往左扫描时，每次贪心地匹配**第一个（即最靠右的）**符合要求的值，一定不会比其他任何匹配方式差。
>
> 直觉：假设你要找的值是 `x`，任何一个值为 `x` 的位置都能满足"存在"这个条件，但你选中的位置会成为继续往左找 `x-1` 的新边界。选**最靠右**的那个 `x`，能给"找 `x-1`"留出**最大**的搜索空间，不可能让情况变得更差。`down[i]` 同理，只是方向相反（从左往右，每次贪心匹配最靠左的）。

有了这个引理，`up[i]` 和 `down[i]` 都可以用一次独立的线性扫描算出，对每个 `i` 都重新扫一次，总复杂度 O(N²)。

### C++ 代码（O(N²) 暴力，拿子任务 1、2 的分）
```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    scanf("%d", &n);
    vector<int> p(n + 1);
    for (int i = 1; i <= n; i++) scanf("%d", &p[i]);

    vector<int> up(n + 1), down(n + 1);

    // up[i]：以 i 结尾的最长"连续 +1 上升"子序列长度
    for (int i = 1; i <= n; i++) {
        int target = p[i] - 1;
        int r = 0;
        for (int j = i - 1; j >= 1 && target >= 1; j--) {
            if (p[j] == target) { r++; target--; } // 贪心匹配最靠右的 target
        }
        up[i] = r + 1;
    }

    // down[i]：以 i 开头的最长"连续 -1 下降"子序列长度（镜像写法）
    for (int i = 1; i <= n; i++) {
        int target = p[i] - 1;
        int r = 0;
        for (int j = i + 1; j <= n && target >= 1; j++) {
            if (p[j] == target) { r++; target--; } // 贪心匹配最靠左的 target
        }
        down[i] = r + 1;
    }

    int bestLen = 1; // 单独一个数字总是合法的金字塔（半径为 0）
    for (int i = 1; i <= n; i++) {
        int radius = min(up[i] - 1, down[i] - 1);
        bestLen = max(bestLen, 2 * radius + 1);
    }

    printf("%d\n", n - bestLen);
    return 0;
}
```
时间 O(N²)，可以通过子任务 1（N≤100）和子任务 2（N≤1000），但子任务 5（N 可到 100,000）会超时（O(N²) ≈ 10¹⁰）。

### 算法思路二（O(N)，进阶内容：动态规划入门）

> 这部分内容用到了**动态规划（Dynamic Programming, DP）**的核心思想，虽然还没有系统学过，但可以把它当作一次很自然的入门体验。

观察暴力解法：计算 `up[i]` 时，我们在 `P[1..i-1]` 里重新扫描一遍，去找"最靠右的、值为 `P[i]-1` 的位置所对应的 `up` 值"。但是——**这个"最佳的 up 值"，我们在处理位置 `i-1, i-2, ...` 的时候不是已经算过了吗？** 与其每次都重新扫描，不如**边扫描边把每个值出现过的最佳 `up` 值记下来**，下次直接查表，这就是"空间换时间"的**记忆化（Memoization）**思想。

具体做法：开一个数组 `bestUp[v]`，表示"目前为止（扫描到当前位置之前），所有值为 `v` 的位置里，最大的 `up` 值是多少"。从左往右扫描：

```
up[i] = 1 + bestUp[P[i] - 1]     // 接到"比我小 1"的最佳链条后面
bestUp[P[i]] = max(bestUp[P[i]], up[i])   // 更新这个值的最佳记录
```

`down[i]` 同理，只是从右往左扫描，维护 `bestDown[v]`。

这样两次扫描都是 O(N)（加上数组清零 O(值域)），总复杂度降到 O(N + V)，V=100000 是键值的最大值。

### C++ 代码（O(N) 满分做法）
```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    scanf("%d", &n);
    vector<int> p(n + 1);
    for (int i = 1; i <= n; i++) scanf("%d", &p[i]);

    const int MAXV = 100001;

    vector<int> up(n + 1), bestUp(MAXV, 0);
    for (int i = 1; i <= n; i++) {
        int x = p[i];
        up[i] = 1 + bestUp[x - 1];        // 接上"值为 x-1"的最佳链条
        bestUp[x] = max(bestUp[x], up[i]); // 更新记录
    }

    vector<int> down(n + 1), bestDown(MAXV, 0);
    for (int i = n; i >= 1; i--) {
        int x = p[i];
        down[i] = 1 + bestDown[x - 1];
        bestDown[x] = max(bestDown[x], down[i]);
    }

    int bestLen = 1;
    for (int i = 1; i <= n; i++) {
        int radius = min(up[i] - 1, down[i] - 1);
        bestLen = max(bestLen, 2 * radius + 1);
    }

    printf("%d\n", n - bestLen);
    return 0;
}
```

### 用样例验证
以样例 1 `P = [2,1,3,4,2,1]` 为例：`up = [1,1,2,3,2,1]`，`down = [2,1,3,1,2,1]`。最佳顶点在位置 3（值为 3）：`radius = min(2-1, 3-1) = 1`，长度 `2*1+1=3`（对应金字塔 `[2,3,2]`）。答案 `= 6 - 3 = 3`，与样例输出一致。

### 本题要点
- **拆分定长问题**：把"找最优金字塔"拆成"固定顶点 → 求两侧独立的最长链"，是处理"某个特殊位置为中心"类问题的常用套路。
- **贪心匹配引理**：暴力做法本身也需要一个正确性证明（最靠右/最靠左匹配最优），不能凭直觉写代码。
- **DP 的入门直觉——记忆化**：当你发现"每次都在重复做几乎一样的搜索"时，就要想：能不能把之前算过的最佳结果存下来，下次直接查？这正是动态规划最核心的思想（用空间换时间，避免重复计算）。这道题是一个非常好的"DP 启蒙"例子。
- **off-by-one**：一定要分清"点的数量"和"步数/半径"的区别，这是本题最容易失分的细节。

## Problem 6：Spaceship Shuffle（飞船洗牌）

### 题意速览
`N` 个船舱围成一圈（**环形，Circular**），相邻船舱相连（船舱 1 和船舱 `N` 也相连）。第 `i` 个船舱现有 $A_i$ 名船员，目标是 $B_i$ 名。每次花 \$1 可以让一名船员移动到相邻船舱（可以移动多次，每次都要付费）。求达到目标所需的最少费用。保证 `sum(A) = sum(B)`。

### 算法思路

**第一步：想象成一条直线（非环形）会怎么做？**

假设船舱排成一条**直线**而不是环，设 $D_i = A_i - B_i$（第 `i` 个船舱的"盈余"，正数表示要往外移出这么多人）。船舱 `i` 和 `i+1` 之间那条边上，必然要净流过 $S_i = D_1 + D_2 + \ldots + D_i$ 个人（**前缀和，Prefix Sum**）——不管中间怎么绕，跨过这条边的人数净值是确定的，跟前面 D 值的总和相等（因为前 `i` 个船舱的总盈余，只能通过这一条边跟外界"排"出去）。所以直线情形的答案就是 $\mathrm{sum}(|S_i|)$（`i` 从 1 到 `N-1`），非常直接。

**第二步：环形怎么办？**

环形比直线多了一条"首尾相连"的边。如果把这条边上净流过的人数记为一个待定变量 `t`，可以推出：跨过第 `i` 和 `i+1` 号船舱之间那条边的净人数是 $t + S_i$（$S_i$ 同上定义，`i` 从 1 到 `N`，其中 $S_N = 0$，因为总人数守恒）。总费用就是：

```
cost(t) = sum_{i=1}^{N} |t + S_i|
```

这是一个非常经典的式子：**要让若干个 `|x - c|` 之和最小，`c` 应该取这些 `x` 的中位数（Median）**。这里我们要最小化的是关于 `t` 的和式，等价于取 $t = -\mathrm{median}(S_1, \ldots, S_N)$。

所以算法是：
1. 计算 $D_i = A_i - B_i$，再计算前缀和 $S_i$。
2. 把 $S_1, \ldots, S_N$ **排序（Sort）**，取中位数 `m`。
3. 答案 = $\mathrm{sum}(|S_i - m|)$。

- 子任务 1（除船舱 1 外全为 0）：所有人都从船舱 1 出发，可以直接用直线情形的思路手动分析。
- 子任务 2（存在最优解不经过"1 和 N 之间"这条边）：等价于直线情形，$\mathrm{sum}(|S_i|)$（`i=1..N-1`）即为答案，帮助理解"破环成链"的意义。
- 子任务 3（N ≤ 1000）：即使 O(N²)（枚举每一种"从哪里剪开这个环"）暴力也能过，可作为验证中位数结论的手段。
- 子任务 4（一般情况）：上面 O(N log N) 的中位数做法即可满分。

### 复杂度
时间 O(N log N)（排序占主导），空间 O(N)。注意 $S_i$ 最大可达约 `10^5 * 10^5 = 10^10`，**必须用 `long long`**，否则会溢出。

### C++ 代码
```cpp
#include <bits/stdc++.h>
using namespace std;

int main(){
    int n;
    cin >> n;
    vector<long long> a(n), b(n);
    for (auto &x : a) cin >> x;
    for (auto &x : b) cin >> x;

    vector<long long> s(n);
    long long running = 0;
    for (int i = 0; i < n; i++) {
        running += (a[i] - b[i]);
        s[i] = running; // s[n-1] 必然等于 0
    }

    vector<long long> sorted_s = s;
    sort(sorted_s.begin(), sorted_s.end());
    long long median = sorted_s[n / 2]; // 中位数（N 为偶数时取中间偏右的那个也成立）

    long long ans = 0;
    for (int i = 0; i < n; i++)
        ans += llabs(s[i] - median);

    cout << ans << endl;
    return 0;
}
```

### 用样例验证
样例 1：`A=[5,2,1,6,5,1]`，`B=[3,3,2,7,3,2]`，`D=[2,-1,-1,-1,2,-1]`，前缀和 `S=[2,1,0,-1,1,0]`。排序后 `[-1,0,0,1,1,2]`，中位数取 `0`：`|2|+|1|+|0|+|-1|+|1|+|0| = 5`，与样例输出一致。

### 本题要点
- **破环成链（Breaking a Circle into a Chain）**：遇到环形结构，先想"如果是一条直线会怎么做"，往往能找到主要思路，再处理"多出来的那一条边"。
- **前缀和（Prefix Sum）**：把"跨过某条边的净流量"转化成前缀和，是处理一维分配 / 搬运类问题的通用技巧。
- **中位数最小化绝对值之和（Median Minimizes Sum of Absolute Deviations）**：这是一个值得牢记的数学事实，出现频率很高，遇到"minimize sum of |$x_i$ - c|"的题目要第一时间想到它。
- **数据范围与 `long long`**：先估算变量可能达到的最大值，再决定用 `int` 还是 `long long`，这题是一个典型的"不开 long long 见祖宗"的例子。

## 冲刺 AIO 高分的关键学习点（跨题总结）

1. **先拿部分分，再冲满分（Subtask Fishing）**：几乎每道题都设置了"可以用更简单/更暴力方法解决"的子任务（比如 P5 的子任务 1、2，P6 的子任务 1、2、3）。比赛中优先写出暴力拿到这部分分数，再考虑优化到正解，好过"想不出正解就交白卷"。

2. **前缀 / 后缀预处理（Prefix / Suffix Aggregates）**：P3（前缀最大值/后缀最小值）、P4（本质上是相邻项的和）、P6（前缀和）都用到了"预处理一遍数组，之后 O(1) 查询"的思想，这是竞赛中最常见的基本功之一。

3. **贪心正确性要会证明，不能只凭直觉**：
   - **交换论证（Exchange Argument）**：P3 中"今天卖得越少越好"的证明方式。
   - **贪心匹配引理**：P5 暴力解法中"匹配最靠右/最靠左的位置最优"的证明方式。
   - 写贪心算法时，养成习惯问自己："如果我这一步不这么选，会不会存在一种情况变得更差？"

4. **绝对值相关的两个重要工具**：
   - **三角不等式** `|a-x|+|x-b| >= |a-b|`（P4）。
   - **中位数最小化绝对值和**（P6）。
   这两个结论在很多"最小化改动/移动代价"类题目里反复出现，值得专门记住。

5. **环形问题：破环成链**（P6）：遇到"首尾相连"的结构，先想直线版本怎么做，再分析多出来的那条边（或者枚举/用数学方法处理"剪开点"）。

6. **动态规划的第一次接触（P5 进阶部分）**：当暴力算法里出现"大量重复的子问题"时（比如反复在同一段区间里搜索类似的东西），就要开始考虑"能不能把之前的结果存下来，避免重复计算"——这正是 DP 的核心思想，也是后续学习 DP 的重要铺垫。

7. **写代码前先想清楚数据范围，决定用 `int` 还是 `long long`**：本套题里 P6 的前缀和可以到 `10^10`，必须用 `long long`；养成看到 `N` 和数值上限就估算"最坏情况下会有多大"的习惯，能避免很多不必要的溢出（Overflow）错误。

8. **注意"点数"和"步数"的区别（Off-by-one）**：P5 是本套题里最容易犯这类错误的地方（`up[i]` 是点数，半径是 `up[i]-1`）。调试这类 bug 时，找一个"顶点两侧长度不同"的样例（比如样例 1、2），比用"两侧长度相同"的样例（比如样例 3）更容易发现问题——后者即使公式写错了，也可能因为对称性巧合地得到正确答案。
